# データ更新手順

この手順書は、`rounds` テーブルの最新データを `docs/rounds_export_ml.csv` に反映し、必要に応じてローカル環境へ再投入し、ML モデルを再学習して反映するための運用メモです。

## 対象

- CSV 更新: `docs/rounds_export_ml.csv`
- 再投入先: PostgreSQL の `rounds` テーブル
- モデル出力先: `api/ml/models/`

## 標準フロー

1. 既存 CSV をバックアップする
2. DB から最新データを CSV へ再エクスポートする
3. 件数と先頭行を確認する
4. 必要なら CSV をローカル DB に再投入する
5. ML モデルを再学習する
6. API を再起動して新モデルを反映する
7. 予測収支シミュレーションの結果を記録する

## 事前条件

- プロジェクトルートでコマンドを実行する
- `docker compose` で `db` と `api` が起動している
- 再学習を行う場合は、ホスト側に Python 実行環境がある
- 例では `/tmp/ml_venv/bin/python` を使う

## 1. 既存 CSV のバックアップ

更新前の CSV を残しておくと、件数差分や精度劣化の切り分けがしやすくなります。

```bash
cp docs/rounds_export_ml.csv "docs/rounds_export_ml.$(date +%Y%m%d_%H%M%S).bak.csv"
```

## 2. DB から CSV を再エクスポート

もっとも単純で再現しやすい方法は `db` コンテナから `psql` で書き出す方法です。

```bash
docker compose exec -T db psql -U "${POSTGRES_USER:-rocket}" -d "${POSTGRES_DB:-rocket}" -t -A -F',' -c \
  "SELECT id, multiplier, recorded_at FROM rounds ORDER BY recorded_at" \
  > docs/rounds_export_ml.csv
```

ヘッダー付きで出力したい場合は、以下でも構いません。

```bash
{
  echo 'id,multiplier,recorded_at'
  docker compose exec -T db psql -U "${POSTGRES_USER:-rocket}" -d "${POSTGRES_DB:-rocket}" -t -A -F',' -c \
    "SELECT id, multiplier, recorded_at FROM rounds ORDER BY recorded_at"
} > docs/rounds_export_ml.csv
```

このリポジトリの学習スクリプトは先頭 1 行をヘッダーとしてスキップするため、通常はこちらのヘッダー付き形式を推奨します。

## 3. CSV の確認

出力直後に最低限これだけ確認します。

```bash
head -n 3 docs/rounds_export_ml.csv
wc -l docs/rounds_export_ml.csv
```

確認ポイント:

- 先頭行が `id,multiplier,recorded_at` になっている
- `recorded_at` が昇順で並んでいる
- 想定件数から大きく減っていない
- `multiplier` 列に空行や文字列が混ざっていない

## 4. 必要ならローカル DB へ再投入

CSV を検証用のローカル DB に流し込みたい場合は `scripts/load_csv_as_new_rounds.sh` を使います。
このスクリプトは `multiplier` 列だけを読み取り、現在時刻基準の新しい時系列データとして `rounds` に入れ直します。

```bash
TRUNCATE_FIRST=1 STEP_SECONDS=5 ./scripts/load_csv_as_new_rounds.sh docs/rounds_export_ml.csv
```

オプション:

- `TRUNCATE_FIRST=1`: 既存の `rounds` を削除してから投入する
- `STEP_SECONDS=5`: レコード間隔を 5 秒で再構成する

注意:

- このスクリプトは元の `recorded_at` を保持しません
- 検証用データの作り直しには向いていますが、本番データの厳密な復元には向きません
- 現在のスクリプトは `docker-compose` コマンドを前提にしているため、必要に応じて環境側でエイリアスを用意してください

## 5. ML モデルを再学習

CSV 更新後に予測モデルも更新する場合は、ホスト側で学習スクリプトを実行します。

```bash
/tmp/ml_venv/bin/python scripts/ml_model.py --csv docs/rounds_export_ml.csv
```

学習結果として、以下のファイルが更新されます。

- `api/ml/models/multiclass.pkl`
- `api/ml/models/binary.pkl`
- `api/ml/models/thresholds.json`

補足:

- `api` コンテナには `docs/` がマウントされていないため、`docs/rounds_export_ml.csv` を直接参照してコンテナ内学習する運用は扱いづらいです
- このため、CSV をホスト側に置いたまま学習し、出力先だけ `api/ml/models/` に書く形を標準とします

## 6. API を再起動して反映

モデルファイルを書き換えたら API を再起動します。

```bash
docker compose restart api
```

必要ならヘルスチェックも確認します。

```bash
curl -fsS http://localhost:8001/api/v1/health
```

## 7. 更新後の確認

最低限、以下を確認します。

```bash
ls -l api/ml/models
docker compose logs api --tail=50
```

確認ポイント:

- `api/ml/models/` の更新時刻が今回の学習時刻になっている
- API 再起動後にモデル読み込みエラーが出ていない
- 予測画面または関連 API で明らかな異常がない

## 8. 予測収支シミュレーションの記録

可能です。記録先は `docs/ml_simulation_results.md` を正本として扱います。
CSV 更新や再学習を行ったあと、予測収支シミュレーションを回した場合は同じタイミングで記録も更新してください。

### 初期化手順

ここでいう「予測収支シミュレーションの初期化」は、`docs/ml_simulation_results.md` の記録ファイルを消すことではなく、サイト上で表示される予測収支シミュレーションの元データである `prediction_evals` を 0 件に戻すことを指します。

手順:

1. 必要なら現在の集計値を `docs/ml_simulation_results.md` に記録する
2. 認証付きで `DELETE /api/v1/evals` を実行する
3. `GET /api/v1/evals/stats` で `total=0` を確認する
4. フロントの予測比較表示がリセットされたことを確認する

API 実行例:

```bash
TOKEN=$(curl -sS -X POST https://rocket.dreami.jp/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"YOUR_USERNAME","password":"YOUR_PASSWORD"}' \
  | python3 -c 'import sys, json; print(json.load(sys.stdin)["access_token"])')

curl -sS -X DELETE https://rocket.dreami.jp/api/v1/evals \
  -H "Authorization: Bearer $TOKEN"

curl -sS https://rocket.dreami.jp/api/v1/evals/stats
```

返却例:

```json
{"deleted":3477}
```

初期化の判断例:

- 実運用サイトの予測収支シミュレーションを 0 から再集計したい
- OCR 修正後のクリーンデータだけで予測評価を取り直したい
- モデル再学習後、古い予測評価を混ぜずに新しい評価だけ見たい

注意:

- `DELETE /api/v1/evals` は `prediction_evals` だけを削除し、`rounds` は削除しない
- サイト上の「予測収支シミュレーション」「的中率集計」「予測比較表示」は 0 からやり直しになる
- ドキュメント記録を初期化したい場合は別作業として `docs/ml_simulation_results.md` をバックアップして整理する
- 初期化後の最初の記録には、何を理由に評価データをリセットしたかを補足メモに 1 行残す

最低限、以下を残します。

- 実施日
- 使用した CSV 件数
- 対象期間
- モデル条件または再学習条件
- 予測件数
- 色別の的中件数、オーバー件数、的中率、収支
- 合計収支
- 補足メモ

追記先の見出し例:

```md
## 予測収支シミュレーション記録

### 第N回 スナップショット（YYYY-MM-DD）
```

更新時のルール:

- 新しい記録を上に追記する
- 収支の単位は表見出しに明記する
- 収支計算式が変わる場合は、その回の直下に式を残す
- 実運用シミュレーションとテスト用シミュレーションは混在させず、対象期間を明記する

## 9. トラブルシュート

### CSV の件数が急減した

- `rounds` テーブル自体の件数を確認する
- 直近のクリーニングや `TRUNCATE` 実行有無を確認する
- バックアップした CSV と `wc -l` で差分を見る

### 学習後に予測が極端に片寄った

- 特徴量ロジック変更の有無を確認する
- train と inference で同じ特徴量定義を使っているか確認する
- CSV 更新だけでなく、コード差分が混ざっていないか確認する

### 再投入スクリプトが失敗する

- `docker-compose` コマンドが使えるか確認する
- `docs/rounds_export_ml.csv` に有効な数値行が入っているか確認する
- `POSTGRES_USER`, `POSTGRES_DB` の環境変数が compose 設定と一致しているか確認する

### 記録の形式が回ごとにぶれる

- `docs/ml_simulation_results.md` のテンプレートに沿って追記する
- 列名を変える場合は過去記録との比較ができる形にそろえる
- 不明値は空欄ではなく `-` または `スキップ` に統一する

## 10. 最短コマンド例

CSV 更新からモデル反映までを最短で行う場合は以下です。

```bash
cp docs/rounds_export_ml.csv "docs/rounds_export_ml.$(date +%Y%m%d_%H%M%S).bak.csv"
{
  echo 'id,multiplier,recorded_at'
  docker compose exec -T db psql -U "${POSTGRES_USER:-rocket}" -d "${POSTGRES_DB:-rocket}" -t -A -F',' -c \
    "SELECT id, multiplier, recorded_at FROM rounds ORDER BY recorded_at"
} > docs/rounds_export_ml.csv
head -n 3 docs/rounds_export_ml.csv
wc -l docs/rounds_export_ml.csv
/tmp/ml_venv/bin/python scripts/ml_model.py --csv docs/rounds_export_ml.csv
docker compose restart api
```
