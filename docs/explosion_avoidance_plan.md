# 爆発回避ロジック 計画と初期計測

## 目的

- 低倍率ラウンド（<=1.20、<=2.00）を事前に検知してエントリー回避する。
- 重要指標は取りこぼし最小化（回避対象の再現率）。
- 運用目標は「回避率 90% 以上（Recall >= 0.90）」。

## 方針

- 2つの回避タスクを分けて評価する。
  - タスクA: 次ラウンドが <=1.20 か
  - タスクB: 次ラウンドが <=2.00 か
- 予測確率が閾値以上なら「回避フラグ（skip）」を立てる。
- 誤って回避する（偽陽性）は許容するが、見逃し（偽陰性）を最小化する。

## データ・評価条件

- データ: docs/rounds_export_ml.csv（9290件）
- 特徴量: scripts/ml_model.py と同等（WINDOW=30, 14特徴量）
- 分割: 時系列 80/20（shuffle=False）
- モデル: LightGBM 2値分類
- 評価:
  - ROC-AUC, PR-AUC
  - Recall >= 0.90 を満たす閾値
  - その閾値での Precision, FPR, Skip Rate, Missed Positive Rate

## 初期計測結果（2026-05-18）

| 指標 | タスクA (<=1.20) | タスクB (<=2.00) |
|------|------------------|------------------|
| ROC-AUC | 0.9270 | 0.9402 |
| PR-AUC | 0.6815 | 0.9293 |
| 閾値（Recall>=0.90） | 0.5710 | 0.5960 |
| Recall | 0.9008 | 0.9006 |
| Precision | 0.5464 | 0.8743 |
| FPR | 0.1761 | 0.1507 |
| Skip Rate | 0.6857 | 0.4460 |
| Missed Positive Rate | 0.0992 | 0.0994 |

解釈:
- <=2.00 回避は高精度（PR-AUC/Precisionが高い）で、実運用しやすい。
- <=1.20 回避は難度が高く、Recall 0.90達成時にSkip Rateが高め。

## トレンド併用（仮説検証）

仮説:
- 1.20以下の移動平均確率が上昇し始める局面で、低倍率頻度が増える。

検証ルール（タスクA）:
- p12: モデルAの予測確率
- t12_90: Recall>=0.90 となる閾値（0.5710）
- rolling_prob12: 直近30件内の <=1.20 割合
- trend_up: rolling_prob12 の3ステップ差分 > 0
- 回避フラグ: (p12 >= t12_90) OR (rolling_prob12 >= 0.22 AND trend_up)

結果:
- Recall: 0.9150
- Precision: 0.4668
- Skip Rate: 0.6263
- Missed Positive Rate: 0.0850

解釈:
- トレンド併用で見逃し率は改善（0.0992 -> 0.0850）。
- ただし Precision は低下し、過剰回避が増える。

## 運用案（段階導入）

1. 第一段階（即時導入候補）
- <=2.00 回避モデルを優先導入。
- 閾値は Recall 0.90 を下限に、Skip Rate 上限で再調整。

2. 第二段階（慎重導入）
- <=1.20 は単独モデルでなく、トレンド併用の条件設計を継続。
- 「見逃し率」と「スキップ率」のトレードオフを可視化して閾値を決定。

3. 第三段階（検証強化）
- ウォークフォワード検証（時系列CV）で期間ごとの安定性を確認。
- 実運用ログで回避成功率、機会損失、DD改善を追跡。

## 次回計測タスク

- 閾値グリッドで回避率-スキップ率カーブを作成（特に<=1.20）。
- トレンド条件の最適化（0.22、3ステップ差分の感度分析）。
- 「連続低倍率ストリーク」特徴と組み合わせたルール比較。
